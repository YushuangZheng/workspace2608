# 双臂在线关系估计正式评测 v1 报告

## 结论

正式 v1 **没有通过全部预注册门槛**。70 个协议 trial 全部唯一落盘，七类条件的物理与
推断压缩序列均为 `70/70` 精确一致，四个要求保持任务成功的条件为 `40/40` 成功；但
`prolonged_both_hold` 只有 `7/10` 在全部 2 秒干预窗口维持物理 `both`。因此物理条件
实现总计为 `67/70`，低于协议要求的 `70/70`，硬审计在首个失败 seed 8401 处正确拒绝。

这三条不是关系估计漏检：发送臂物理边在延长双持期间真实解除，估计器还提前 40–80 ms
给出同方向变化。v1 证明当前估计器能准确描述所发生的关系，但没有证明现有干预器能在
所有 seed 中制造完整 2 秒双持。完整双臂策略训练继续禁止启动。

## 三条硬失败的逐步归因

三个失败 seed 都进入了标准 `none → left_only → both → right_only → none`，任务最终成功。
干预器在 `TRANSFER` 固定两臂 hold pose、保持双夹爪闭合并冻结 phase clock 100 步；但接收
臂承担载荷后，发送臂仍会因内部力和物体沉降失去双指接触：

| seed | 2 秒窗口内物理 `both` | 物理转为 `right_only` | 推断转为 `right_only` | 提前量 |
|---:|---:|---:|---:|---:|
| 8401 | 36/100 步（0.72 s） | offset 36 | offset 34 | 40 ms |
| 8406 | 31/100 步（0.62 s） | offset 31 | offset 27 | 80 ms |
| 8408 | 85/100 步（1.70 s） | offset 85 | offset 81 | 80 ms |

物理真值变化后一直保持 `right_only` 至干预窗口结束，不是三步迟滞边缘造成的单点差异。
对应推断没有锁存到 `both`，而是稍早识别发送边失去。这支持“干预保持动作不够顺应”的
解释，不支持放松关系估计阈值。

## 审计结果

第一次硬审计还暴露一个审计器数值问题：JSON 使用 Python double 控制周期，NPZ 保存
float32，0.22 s 重算为 `0.219999995...`，原 `1e-10` 等值容差过严。容差只调整为
`1e-7`，远小于最紧的 0.10 s 协议门；没有改试验、指标或门槛。修复后硬审计按预期停止于：

```text
bimanual_relation__prolonged_both_hold__seed_8401.npz 的物理干预没有按定义成立
```

冻结 v3 物理专家、物理数据集和正式 v1 文件均未修改。

## v2 允许修改与禁止项

v2 只允许修复 `prolonged_both_hold` 的动作实现：在延长窗口中让左右笛卡尔目标跟随实测
当前末端，而不是持续拉回固定 hold pose，同时保持双夹爪闭合和 phase clock 冻结。这样
减少两臂刚性目标冲突，是否能维持真实双持必须先用新 development seed 验证。

禁止修改：

- 关系估计器、标定配置和任何 F1/延迟阈值；
- 物理关系真值、接触门、任务环境或脚本专家正常路径；
- v1 正式 seed、结果或报告数字；
- 根据 v1 失败重跑相同 seed 并替换结果。

若开发验证成立，v2 必须使用新正式 seed 和新源码指纹。由于干预模块属于正式源码，最严谨
做法是重新运行完整七条件矩阵，而不是只补跑长双持后与 v1 拼接为单一成功率。
